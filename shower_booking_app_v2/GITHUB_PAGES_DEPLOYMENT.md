# GitHub Pages 部署指南

恭喜您已经将应用上传到GitHub！现在，让我们将其部署为一个可公开访问的网站。GitHub Pages是GitHub提供的免费静态网站托管服务，非常适合部署我们的洗浴预约应用。

## 步骤一：确保您的仓库配置正确

1. 登录您的GitHub账号
2. 进入您上传应用的仓库页面
3. 检查仓库中是否包含以下文件：
   - `index.html`（主应用文件）
   - `README.md`（说明文档）
   - 其他必要的配置文件

## 步骤二：启用GitHub Pages

1. 在仓库页面中，点击顶部的"Settings"（设置）选项卡
2. 在左侧导航栏中，向下滚动并点击"Pages"选项
3. 在"Source"（源）部分，点击下拉菜单并选择：
   - 分支：通常选择 `main` 或 `master`
   - 文件夹：选择 `/ (root)`（根目录）
4. 点击"Save"（保存）按钮

## 步骤三：等待部署完成

1. 保存设置后，GitHub会开始构建您的网站
2. 页面顶部会显示部署进度和状态
3. 部署完成后，您会看到一个绿色的成功消息，显示"Your site is published at..."（您的网站已发布在...）
4. 复制显示的URL，这就是您应用的公开访问地址

## 步骤四：配置Firebase（多用户版本）

如果您部署的是多用户版本（使用云数据库），还需要完成以下步骤：

1. 确保您已经按照`README_FIREBASE.md`的指南创建了云数据库项目
2. 在GitHub Pages网站上打开应用
3. 打开浏览器的开发者工具（通常按F12或Ctrl+Shift+I）
4. 检查控制台是否有任何错误信息
5. 如果有连接错误，请确认您的云数据库配置是否正确，并且安全规则允许公开访问

## 步骤五：测试您的应用

1. 打开部署完成后提供的GitHub Pages URL
2. 测试应用的所有功能：
   - 填写表单并提交预约
   - 检查预约成功提示
   - 测试导出功能（如果是多用户版本，尝试从不同设备提交预约后再导出）
3. 确认所有功能正常工作

## 步骤六：分享您的应用

1. 复制GitHub Pages URL
2. 将链接分享给需要使用预约系统的用户
3. 对于管理员，可以直接使用页面底部的导出功能下载预约数据

## 故障排除

如果您遇到任何问题，请检查以下几点：

1. **页面显示空白或错误**：
   - 确认`index.html`文件位于仓库根目录
   - 检查浏览器控制台是否有错误信息
   - 确认所有外部资源（如Tailwind CSS、Font Awesome）的链接是否正确

2. **多用户版本数据不同步**：
   - 确认Firebase配置是否正确
   - 检查Firebase实时数据库的安全规则是否允许读写
   - 确认网络连接正常

3. **部署状态显示错误**：
   - 检查GitHub仓库中的文件结构
   - 确认`index.html`文件存在且格式正确
   - 尝试重新保存GitHub Pages设置

## 自定义域名（可选）

如果您想使用自己的域名而不是GitHub提供的域名，可以：

1. 在您的域名注册商处设置CNAME记录，指向您的GitHub Pages域名
2. 在GitHub Pages设置中添加您的自定义域名
3. 按照GitHub的指示完成SSL证书设置

## 更新应用

当您需要更新应用时，只需：

1. 将更新后的文件推送到GitHub仓库
2. GitHub Pages会自动重新构建并部署您的网站
3. 通常在几分钟内完成更新

如有任何其他问题，请参考[GitHub Pages官方文档](https://docs.github.com/cn/pages)或联系GitHub支持。
